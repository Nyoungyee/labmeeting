# Lab Meeting 토론 플러그인 설계 명세서

생물학 연구 질문을 5인 랩미팅 구조로 분해·토론·검토하는 Claude Code 플러그인.

## 0. 왜 만드는가

코드 작업에는 **공짜 오라클**이 있습니다. 컴파일되는가, 테스트가 통과하는가.
연구 질문에는 그것이 없습니다. 기존의 모델 승급형 플러그인(superpowers-v, frugal 등)이
연구 영역에 그대로 적용되지 않는 이유입니다.

이 플러그인은 "정답 여부" 판정을 포기하고, **기계적으로 확인 가능한 대리 지표**로 대체합니다.

| 대리 지표 | 측정 방법 |
|---|---|
| 근거 충실성 (grounding) | 모든 주장이 실존하는 문헌에 대응되는가 (PMID/DOI 검증) |
| 반증 내성 | 전담 반대 에이전트가 찾아온 반대 증거를 견디는가 |
| 관점 간 불일치 | 서로 다른 관점의 에이전트들이 갈리는가 (갈림 자체가 신호) |
| 주장 유형 분리 | 확립된 사실 / 논쟁 중 / 추론 / 추측이 구분되어 있는가 |

**핵심 원칙: "모르겠다"는 실패가 아니라 유효한 출력이다.**
현재 문헌으로 결론이 나지 않는 질문에 억지로 결론을 내는 것이 진짜 실패입니다.

## 1. 역할 구성

### 1.1 교수 (Professor) — Opus

**가장 중요한 제약: 교수는 자료조사를 하지 않는다.**

- 검색 도구(PubMed, bioRxiv, 웹 검색) 접근 **금지**
- 외부 자료를 새로 가져오지 않음
- 오직 **학위생과 포스닥이 테이블 위에 올린 내용에 대해서만** 발언
- 자신이 알고 있다고 생각하는 사실도 근거 없이 주장하지 않음.
  대신 "그건 누가 확인해봤나?"라고 되물어 학위생에게 과제를 되돌려줌

**하는 일**
1. 토론 개시 전: 포스닥이 정리한 의제를 받아 토론 순서를 정함
2. 토론 중: 매 라운드가 아니라 **개입이 필요할 때만** 끼어듦
   - 논의가 겉돌 때 질문을 좁혀줌
   - 근거 없는 주장이 합의처럼 굳어질 때 제동
   - 중요한 갈림길에서 "그 두 가설을 구분할 실험이 뭔가?"라고 물음
   - 보류함(parked)에 있던 아이디어를 다시 꺼냄
3. 토론 종료 후: 최종 정리. 단, **승자를 뽑지 않음** (§4 참조)

**발언 제한**: 한 라운드에 최대 2회, 각 5문장 이내.

### 1.2 포스닥 (Postdoc) — Sonnet

1. **사전 정리 (토론 전)**: 의제(agenda) / **보류함(parked)** 분리. 삭제가 아님. 보류 사유 한 줄 필수.
   > 가지치기 기준은 "주제 적합성"이 아니라 "이 랩에서 실제로 검증 가능한가". 포스닥은 삭제 권한이 없고 보류 권한만 있음.
2. **토론 중**: 실현 가능성 담당 (비용, 시간, 장비, 대조군 설계).
3. **토론 후**: 회의록 작성.

### 1.3 학위생 3인 — Haiku 또는 Sonnet (병렬)

**성격이 아니라 맡은 관점으로 나눈다.** 같은 기반 모델이면 오류가 상관되어 수렴한다. 역할로 강제해야 수렴이 구조적으로 막힌다.

| 에이전트 | 전담 관점 | 반드시 가져와야 하는 것 |
|---|---|---|
| **G1 (지지)** | 기전과 지지 증거 | 주된 가설, 뒷받침하는 1차 문헌 |
| **G2 (반대)** | 반대 증거, 재현 실패, 음성 결과 | **역할상 반드시 반대편.** 못 찾으면 "찾았으나 없었다"를 검색어와 함께 명시 |
| **G3 (대안)** | 대안 설명, 방법론적 결함, 교란변수 | 같은 데이터를 설명하는 다른 가설, 원 논문의 한계 |

## 2. 발언 규칙

### 2.1 근거 의무화

| 태그 | 의미 |
|---|---|
| `[EST]` | 확립된 사실 — PMID/DOI 필수 |
| `[CONTESTED]` | 논쟁 중 — 양쪽 PMID 필수 |
| `[INFER]` | 추론 — 출발점 PMID + 추론 단계 |
| `[SPEC]` | 추측 — 근거 없음 명시 |

- 태그 없는 주장은 회의록에서 자동 제외
- `[SPEC]`은 환영. 다만 결론의 근거가 될 수 없음
- 교수 발언은 `[INFER]`/`[SPEC]`/타인 PMID 인용만 가능

### 2.2 인용 검증

회의록 작성 전 모든 PMID/DOI 검증. 실존 + 제목·연도·저널 대조. 실패 시 `⚠ UNVERIFIED` + `[SPEC]` 강등.

## 3. 파이프라인

Phase 0 교수 범위 판단 (사실 조회면 종료) → Phase 1 G1/G2/G3 병렬 조사 → Phase 2 포스닥 의제/보류 → Phase 3 토론 (최대 N라운드, 기본 3; 교수 라운드당 최대 2회) → Phase 4 인용 검증 (실패 시 강등, 필요하면 Phase 3 1회 재실행) → Phase 5 교수 최종 정리 + 회의록.

**종료 조건**: 수렴 / 증거 소진 / 라운드 초과. **라운드 초과는 실패가 아님.**
**교착 시**: 교수가 보류함에서 1~2개 복귀.

## 4. 출력 — 승자를 뽑지 않는다

회의록 8개 섹션: 교수 정리 / 합의된 내용 / 남은 이견(생략 금지) / 조건부 결론 / 미해결 질문 / 다음에 확인할 것 / 보류함 / 검증 리포트. 형식은 `skills/minutes/SKILL.md`.

## 5. 플러그인 구조 · 도구 권한 · 모델

| 에이전트 | 검색 | 모델 |
|---|---|---|
| professor | **없음** | Opus |
| postdoc | 검증·확인 목적만 | Sonnet |
| student ×3 | 전체 | Haiku / Sonnet |

유형별 조정: A 사실 조회 → 학위생 1명 + 검증 / B 문헌 종합 → 표준 / C 기전·인과 → Sonnet, N=4 / D 가설·실험 설계 → 표준 + 보류함 재개방 1회.

## 6. 평가셋 먼저

질문 20~30개 + "좋은 답의 조건". 단일 에이전트 베이스라인과 **반드시 비교**. multi-agent debate 효과는 과제에 따라 들쭉날쭉하다는 보고가 있음.

## 7. 알려진 실패 양상

토론 연극 / 합의 붕괴(G2 무력화) / 교수 과잉 개입 / 포스닥 과잉 가지치기 / 가짜 수렴 / 단일 결론 압축.

# 부록: 구현 결정 (2026-10-05)

## A. 포크 대상과 재사용 범위

[dyubero/conclave](https://github.com/dyubero/conclave) (MIT)를 git 히스토리째 포크. 재사용: Workflow 스크립트 골격(라운드 루프, `parallel` 팬아웃, 구조화 스키마, 이견 보존 필드), 플러그인 매니페스트. 제거: 모델 정체성 위장, 인지 스타일 로스터, 비준 투표(합의 추구 → 명세와 충돌), HTML 뷰어·라이브 서버, 스페인어 기본.

## B. 오케스트레이션 = Workflow 스크립트

`skills/labmeeting/labmeeting.workflow.mjs` 하나가 Phase 0~5를 결정적으로 제어. 에이전트는 `agent(prompt, { agentType: 'labmeeting:<role>', model })`로 `agents/*.md` 정의를 호출.

- 교수 검색 차단: `agents/professor.md` frontmatter `tools: Read` (allowlist → MCP·WebSearch 전부 제외). 도구 0개면 스폰 에러라 `Read` 하나 남김.
- 포스닥 제한: 프롬프트 수준 ("검증 목적만"). `tools:` allowlist로 MCP를 빼면 검증 자체가 막히므로 하드 제한은 두지 않음.
- 학위생: 도구 제한 없음. MCP는 ToolSearch로 로드.
- 모델은 md의 `model:`과 스크립트 `opts.model` 양쪽에 지정 (`args.models`로 덮어씀).

## C. 인용 검증

Workflow 안에서는 파일시스템·Node API를 못 쓰므로 Python 스크립트 대신 **포스닥 에이전트 + PubMed MCP / CrossRef WebFetch**. 12건 단위 배치 병렬. 판정·강등은 스크립트가 결정적으로 수행(`verifyPass`). 네트워크 오류는 `UNCHECKED`로 분리, 강등 없음.

## D. 교수 개입

매 라운드 종료 시 교수에게 `CHECK_SCHEMA` 1회 질의. `intervene=false`가 기본. 개입은 `maxItems: 2`, 각 `maxLength: 700`. `converged`는 1라운드에서는 무시(가짜 수렴 방지), 2라운드부터 종료 조건. `stalled`면 보류함 [0] 자동 재개방, 유형 D는 1라운드 후 기본 재개방.

## E. 회의록

스크립트가 `minutes_md`를 결정적으로 렌더. §2에는 검증 통과한 EST/CONTESTED만, §3 비면 경고 행, §7에 재개방 표시. 메인 루프는 Write만.

## F. 모드

- `full`: 전체. Phase 0에서 유형 A 판정 시 자동으로 quick 경로.
- `quick`: G1 1명(세 관점 겸임) → 검증 → 교수 정리.
- `resume`: 명령어가 이전 회의록 §7·§3을 파싱해 `parked`·`context`로 전달. Phase 0 생략, 학위생은 보류 항목만 조사.

## G. 생략

HTML 뷰어, 라이브 뷰, `--purist`, 다국어 스타일셋, Python 검증 스크립트, 평가셋 질문(사용자 영역 — `eval/questions.md` 템플릿만).

## H. 검증 방법

`test/mock-run.mjs`: 에이전트를 스텁으로 바꿔 스크립트를 실행. 확인 항목: 태그 없는 주장 제외, 가짜 PMID → SPEC 강등 + 1라운드 재실행, 1라운드 수렴 무시, 교수 reopen 개입, quick/resume 분기, 회의록 섹션 내용.

## I. 비판 담당 포스닥 추가 (2026-10-05, 사용자 요청)

포스닥을 2인으로 분리. 두 번째 포스닥은 토론 전 구간에서 비판만 담당한다 (`agents/postdoc-critic.md`).

### G2(반대 학위생)와의 역할 분리

| 사람 | 공격 대상 | 도구 |
|---|---|---|
| G2 반대 | **가설**. 반대 문헌을 찾아온다 | 전체 검색 |
| 비판 포스닥 | **논증과 회의 과정**. 이미 올라온 추론을 공격한다 | 검증 목적만 |

겹침을 막는 것이 설계의 핵심이다. 비판 포스닥은 새 문헌을 가져오지 않는다.

### 점검 항목

근거불일치 (붙은 PMID가 그 주장을 실제로 지지하는가) / 논리비약 (상관→인과, 충분→필요, in vitro→in vivo, 과발현→생리적 역할) / 교란변수 / 방법론 / 과잉일반화 / **에코** (학위생 반응이 거의 전부 agree·partial이거나 같은 소수 논문만 돌려 인용).

에코 감시가 존재 이유다. 다섯 에이전트가 같은 기반 모델이면 합의는 독립적 확증이 아니라 메아리일 수 있다. Conclave의 red team이 하던 일을 포스닥 직급으로 되살린 것.

### 발언 지점

1. Phase 2 — 포스닥의 의제/보류함 분리를 검토 (과잉·과소 가지치기 감시).
2. Phase 3 — 매 라운드, 포스닥 실현성 발언 뒤 · 교수 점검 앞. 교수가 비판 결과를 보고 개입 여부를 정한다.
3. Phase 5 — "상" 지적과 에코 경보가 교수 최종 프롬프트에 주입된다. 해소되지 않은 "상"에 의존하는 내용은 `can_say`에 넣지 못한다.

### 거부권 (결정적)

`unaddressed_high`가 켜져 있거나 (수렴 시점에) `echo_warning`이 켜져 있으면 교수가 `converged`를 내도 토론이 종료되지 않는다. 스크립트가 라운드를 계속 돌린다 (`criticVetoes`). 증거 소진 종료도 같은 조건으로 막힌다.

이것이 Conclave의 audit veto를 대체한다. 차이: Conclave는 사후 감사가 결론 등급을 낮췄고, 여기서는 사전 거부권이 종료 자체를 막는다.

### 회의록 반영

§5에 해소되지 않은 "상" 지적, §8에 지적 수·거부권 횟수·에코 경보. 8섹션 형식은 유지.

### 비용

라운드당 +1 에이전트, 가지치기 검토 +1. 3라운드 기준 약 +4 호출. `quick` 모드는 비판 포스닥을 쓰지 않는다.

### 심각도 남발 방지

프롬프트에서 "상 남발 시 당신의 상이 무시된다", "트집은 올리지 마라"를 명시. `nothing_found: true`일 때도 `checked`를 필수로 요구해 "문제 없음"이 점검 기록을 동반하게 했다.
